## 4. 你特别要求确认的三件事

### 4.1 API Key「会记忆」是否与项目现有「默认不记住」冲突

**冲突，而且是两处，不是一处。**

| | 主线（1eb3d0b） | 他 |
|---|---|---|
| 复选框初值 | `<input id="remember" type="checkbox" />` **不勾** | `:753` `<input id="remember" type="checkbox" checked />` **默认勾** |
| 提示文案 | 「默认不勾选『记住 Key』，只保存在本标签页内」 | `:1777`「API Key 已保存在当前浏览器中，下次打开会自动回填。」 |
| 「忘记 Key」后 | —— | `:1403` 把 `remember.checked` **又设成 true**（删了 Key 却打开记住） |

**更要命的是这条——静默升级，用户无法回退**（`:1374-1383`）：

```js
const sess = sessionStorage.getItem(KEY_SS);   // 当初"不想记住"才写在这里的
if (sess) {
  document.getElementById('key').value = sess;
  document.getElementById('remember').checked = true;
  localStorage.setItem(KEY_LS, sess);          // ← 搬到长期存储
  sessionStorage.removeItem(KEY_SS);
}
```

含义：**用户只要填过一次 Key，哪怕当初没勾"记住"，下次打开就被永久写进 localStorage，
且复选框被自动勾上**。项目"不勾就只活在本标签页"的承诺在代码层面被抹掉了。
明文 API Key 长期驻留浏览器，这是凭据处置问题，不是偏好问题。

**顺带一个"承诺了做不到"的点**：`/api/analyze` 请求体他传 `{ text, constitution_override, model }`，
但主线 `AnalyzeRequest` 字段是 `text / meal_time / constitution_override / exclude_herbs / session_id`
—— **没有 `model`**，Pydantic 静默丢弃。所以弹窗里的"模型选择"**在主分析路径根本不生效**
（只在主线没有的 `/api/chat` 上生效）。要么后端接线，要么把这一项撤掉，不能留着骗人。

### 4.2 「自动汇总近 7 天记录」的数据存在哪？会不会丢？

**存在浏览器 `localStorage`，键 `ta_diet_log`**（`:817` 读、`:845` 写）。
**会丢**，而且丢得无声无息：

| 场景 | 结果 |
|---|---|
| 清除浏览器数据 / Cookie | 全丢 |
| 换浏览器、换设备、无痕模式 | 看不到（数据跟着 origin 走） |
| 换端口（8000 → 别的） | 全丢（localStorage 按 origin 隔离） |
| 超过 30 天 | 被 `loadDietLog()` 自动过滤掉（`:821`） |
| 超过 300 条 | `logs.length = 300` 截断（`:841-843`） |

没有导出、没有备份、没有服务端副本。对话历史同理（`ta_chat_history`，100 条上限）。

**另一个更隐蔽的问题**：汇总时（`:1715-1719`）取最近 **12 条** → 拼接 → **截断到 1200 字符**，
然后整段 POST 给 `/api/analyze-offline`。而该端点内部（`:61-72`）用**当前系统时间**猜
`meal_time`、用关键词计数猜 `overall_nature` —— 它以为收到的是"一顿饭"。
所以"近 7 天汇总"实际是"把 7 天的词堆在一起，按一顿饭算"，且超出的部分被静默丢掉。

### 4.3 安全提醒的具体措辞与触发逻辑

**措辞**（`:1740`，一字不改）：

> 这是根据近 7 天饮食与当前体质生成的药食同源候选，不是处方；孕期、哺乳期、儿童、慢性病或正在服药者，请先咨询执业医师。

**触发逻辑：无条件静态显示。** 只要（a）近 7 天有记录、（b）返回了推荐，
就把这一行渲染出来。**不收集、不判断用户是否属于这些人群。**

对照主线（`core/app/domain/safety.py`）：

```python
HIGH_RISK_KEYWORDS = ("怀孕","孕妇","备孕","哺乳","喂奶","经期","月经",
                      "小孩","孩子","儿童","婴儿","宝宝","幼儿",
                      "化疗","手术","糖尿病","高血压","心脏病","肾病","肝病",
                      "吃药","服药","中药","西药","过敏")
def detect_high_risk(text): return [kw for kw in HIGH_RISK_KEYWORDS if kw in text]
```

主线是**后端硬拦截**：命中 → `orchestrator.py:128-148` 直接不给具体推荐、改引导就医、
记 `guardrail_applied`。同一个输入「我怀孕了，今天吃了火锅」：

- **主线**：不给推荐，只引导就医（且这条不调用模型，免费）。
- **他**：照常给推荐，底部多一行小字。

**更严重的是对话路径**：我把 `core/app/api/chat.py` 全文读完了 ——
**它既不调 `detect_high_risk`，也不调 `check_blend`**，直接把模型回复返回。
白名单、剂量、禁用表述、高风险人群**四道护栏一道都不走**，只在 system prompt 里
写一句"只从这份候选中选择"（软约束，靠模型自觉）。
这与项目"确定性安全护栏，模型会飘，护栏不能飘"是正面冲突。
