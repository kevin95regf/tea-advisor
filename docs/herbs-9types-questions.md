## 0. 回答前请先看这五条

1. **项目性质**：这是一个**饮食养生方向的茶饮推荐助手**，不是诊疗工具。判断的是「这一味药食同源饮片，日常代茶饮时对该体质的**宜/忌倾向**」，不是开方治病。
2. **对象是饮片不是食材**：34 味均为药食同源品种，用量上限 3–15 g/日，属长期低频摄入。与「一顿吃了半斤」的食材剂量不可同日而语。
3. **判不出来就答 `no_basis`。** 这是本项目的默认路线，不是失败答案。草稿里 97 个格子标 `？`、6 个标 `△`，全是我不敢猜的。**请宁可少标，不要为了填满而给弱依据的结论**——理由见 §1.4。
4. **空白不是安全默认值。** 未被标入 `unsuitable_for` 的饮片**仍会出现在候选集里**（只是排序靠后），再由模型写入推荐文案。所以「应当禁忌却没标 ✗」是实打实的风险，而「应当适宜却没标 ✓」只是推荐质量下降。这也是 §3 把潜在禁忌排在潜在适宜前面的原因。
5. **每个体质至少要有一条 `suitable`，否则功能会崩溃**：`safety.py:filter_by_constitution` 在查不到任何 `suitable_constitutions` 时会抛 `MissingConstitutionDataError`。当前草稿已满足（阴虚 5 / 血瘀 4 / 气郁 8 / 特禀 2），但若作答结果把某体质现有的 ✓ 全部推翻，请明确提示。

## 1. 期望输出格式

### 1.1 每个格子一个对象，一行一条 JSON（JSONL）

```json
{"herb_id":"fuling","herb_name":"茯苓","constitution":"yin_deficiency","verdict":"unsuitable","basis":"evidence","confidence":"high","source":"https://ydz.chp.org.cn/#/item?bookId=1&entryId=374","rationale":"甘淡渗利，阴虚津少者久服更伤津液","reviewer":"<署名/资质>"}
```

### 1.2 字段与取值

| 字段 | 必填 | 取值 | 含义 |
|---|---|---|---|
| `herb_id` | 是 | 见清单括号内英文 id | 与 `herbs.json` 的 `id` 字段对应 |
| `herb_name` | 是 | 中文名 | 冗余字段，防止 id 错位 |
| `constitution` | 是 | `yin_deficiency` / `blood_stasis` / `qi_stagnation` / `special_diathesis` | 新体质 id |
| `verdict` | 是 | `suitable` / `unsuitable` / `caution_only` / `neutral` | 判定结论，见 §1.4 映射 |
| `basis` | 是 | `evidence` / `inference` / `no_basis` | **有依据 / 专业推断 / 无法判定**，见 §1.3 |
| `confidence` | 是 | `high` / `medium` / `low` | 本人对该判定的把握 |
| `source` | 条件必填 | URL 或文献名 | `basis=evidence` 时**必填**；其余填 `null` |
| `rationale` | 是 | ≤ 40 字中文 | 会展示给用户，措辞须避免疗效承诺 |
| `reviewer` | 是 | 署名 + 资质 | 写入 `_constitution_evidence` 的 `reviewed_by` |

### 1.3 `basis` 三值怎么判（这是整个格式的核心）

| 取值 | 定义 | 硬性要求 | 进 herbs.json 吗 |
|---|---|---|---|
| `evidence` | 有**可核对的公开来源**直接支持该结论：药典、《中医体质分类与判定》国标、省级以上中医药主管部门科普、具备资质的专业文献 | 必须给出 `source`（URL 或 书名+页码） | **是**，且写入 `suitable_constitutions` / `unsuitable_for` |
| `inference` | 依据中医药理论做出的**专业推断**，但**拿不出可引用的出处**（例如「按其性味归经理当如此，但我给不出文献」） | `source` 填 `null`，`rationale` 写清推理链 | **否**，暂存答案文件，经第二人复核同意后才可转正 |
| `no_basis` | 该味饮片与该体质**没有明确的宜忌关系**，或证据互相冲突无法取舍 | `rationale` 说明为何无法判定 | **否**，等同于留空 |

> **这条分界线为什么值得较真**：两个数组都咬人。`unsuitable_for` 由 `safety.py` 强制检查——一旦写入，该饮片对该体质**永久退出候选集**；`suitable_constitutions` 决定推荐排序——一旦写入，它会被优先推给用户。把模型推断伪装成有依据，等于把不可审计的判断塞进安全护栏，这正是本项目一路躲开的东西。

### 1.4 `verdict` → `herbs.json` 的回填映射

| verdict | 落到哪个字段 | 效果 |
|---|---|---|
| `suitable` | 把 `constitution` 加入 `suitable_constitutions` | 候选集内**优先**排序 |
| `unsuitable` | 把 `constitution` 加入 `unsuitable_for` | 候选集**直接剔除** + `check_constitution_conflict` 告警 |
| `caution_only` | **不改这两个数组**，改为把 `rationale` 追加进该饮片的 `cautions` | 候选集保留，但每味限取 1 条提示语 |
| `neutral` | 不动 | 进 `neutral_fallback`，可推荐但不优先 |

> `cautions` 目前由 `matcher.py:237` **每味只取第 1 条**，`safety.py` 亦有一部分路径只取前若干条。追加 `caution_only` 文案前要考虑它会不会挤掉原有更重要的禁忌提示——需要的话请注明优先级。

### 1.5 溯源信息落哪里

`herbs.json` 现有的 `suitable_constitutions` / `unsuitable_for` 是**扁平字符串数组，不携带出处**。为了让审计闭环，回填时同步写一个同级的影子字段（草稿阶段已列为挂起项 E2）：

```json
"_constitution_evidence": {
  "blood_stasis": {"basis":"evidence","source":"<URL>","reviewed_by":"<署名>","reviewed_at":"2026-09-17"}
}
```

这样「哪一格是谁、凭什么、什么时候定的」能被机器读出来，也能让前端沿用项目既有的「此项食性未经验证」展示策略。这需要一并改 `app/domain/models.py` 的 `HerbEntry` 并补测试——**本次未做**。

## 3. 已知难点（请优先表态）

这 5 个是草稿明确踩过的坑，不做反问式引导，只陈述分歧点：

1. **血瘀质的寒热两途**：栀子、槐花、决明子、鱼腥草、菊花性寒凉。血瘀可由「寒凝」致，也可由「血热」致，这味药的方向正好相反。**是否应按其他指征（如舌色、痛感性质）区分？还是统一按单一方向处理？**
2. **气郁质的温燥悖论**：理气药多偏温燥（陈皮、橘红、紫苏、佛手），理当适宜；但气郁日久可化火，温燥是否助火？**是否有必要引入兼夹体质的处理约定？**
3. **酸涩药的边界**：乌梅被明确点名（血瘀、气郁均应少吃），但同为酸涩的莲子、酸枣仁、山楂是否同理？**酸涩收敛能否作为一条通用规则，还是必须逐味判断？**
4. **特禀质的整体策略**：这是个体化过敏原问题，不是寒热虚实问题。34 味里没有一味落在官方科普的「发物」清单上，但花类（菊花、槐花、茉莉花、玫瑰花）的花粉交叉过敏是合理担忧。**是接受「几乎不标」，还是应该系统性排查？**
5. **兼夹体质的合并逻辑**：草稿已发现「山楂在血瘀宜用、在阴虚却被留白」的冲突。本项目当前是**单一体质**输入，**多体质命中同一味饮片时如何取舍，需要一条明确规则**。
