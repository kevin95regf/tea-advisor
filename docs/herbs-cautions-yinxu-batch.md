## 0. 这批是什么、不是什么

**是什么**：把项目**自己已有**的 `cautions` 措辞，翻译成机器可执行的 `unsuitable_for` 标注。
每条都能指回 `herbs.json` 的原文，**不含任何外推**。

**为什么值得单独走一批**：`unsuitable_for` 是**硬过滤**（`safety.py:217` / `matcher.py:258`
都是 `if constitution in unsuitable: continue`）。而 `cautions` 属**软约束**——模型可以不听。
（**2026-09-17 更正**：此处原文写「`cautions` 只进 Agent2 的提示词」，与代码不符。真实出口有两处：
① `matcher.py` 兜底路径的 `Recommendation.cautions`，**只取每味第 1 条**；
② `safety.check_blend` 把每条 caution 转成 warning 进 `Basis.guardrail_applied`（进 API 响应）。
两处都比硬过滤软，方向性结论不变，但影响面比原文描述的大。
`herbs.json` 的 `_meta.constitution_extension.cautions_batch.why` 已同步更正。）

这就造成一个当时真实存在的缺口：**阴虚质只有桑椹 1 味「宜」、0 味「忌」**（Step 2 之后），
而 `cautions` 里明明写着生姜「阴虚内热者不宜」、藿香「阴虚火旺者不宜」、
紫苏「阴虚内热者不宜」——**项目已经认定不宜，却挡不住任何东西**。本批就是补这个缺口。

**不是什么**：这不是「外部权威依据」。它是**项目自有数据的一致性修复**——
把已对外展示的口径落实到护栏上。因此：

- 不标 `evidence`，属 **inference（项目自有数据推导）**；
- 与 A1 口径一致：**写入 ≠ 审核通过**，界面照旧标「待验证」；
- **不新增**任何 `review_*` 字段（那是 E2 的决定，见 `pending-items.md`）。

### 1.1 措辞强度分档：**决定「全写」（方案甲）**

1–5 的 `cautions` 是**「…者不宜」**（直截了当），6–10 是**「不宜久服 / 减量 / 慎用」**
（温和档）。两类写进 `unsuitable_for` 的效果完全一样——**都是硬屏蔽**。

分歧点落在 6–10 上，尤其 **茯苓**：它 `cautions` 只写「不宜久服」，而 `suitable` 里有
`痰湿 / 气虚 / 平和`，是味很常配的平性药。硬屏蔽后，阴虚质再也拿不到茯苓。

| 方案 | 内容 | 结论 |
|---|---|---|
| **甲：全写 10 味** | 严格口径全覆盖 | ✅ **已采用**。项目所有者：方向正确比候选数量重要——茯苓对阴虚确实是「不宜久服」，硬屏蔽不会造成方向错误 |
| 乙：只写 5 味（措辞为「不宜」） | 最贴字面 | ❌ 未采用：茯苓/陈皮/薏苡仁/龙眼肉/茉莉花仍会被推给阴虚质，缺口只补上一半 |
| 丙：10 味全写，但 6–10 单列提交 | 便于日后单独回滚温和档 | ❌ 未采用：本次按一份数据改动提交，不额外拆分 |

采用的判据：这 10 味方向**一致**——要么温燥（生姜/橘红/藿香/紫苏/佛手/陈皮/茉莉花/龙眼肉），
要么淡渗利水（茯苓/薏苡仁），都落在阴虚「忌温热燥烈、重伤津液」上。`unsuitable_for`
造成的损失只是**候选减少**；方向判错才是真风险（阴虚被推辛温品）。
按项目原则「宁可失败，也不要看起来能用」，这里应当偏保守。

## 3. 写入方式与实测影响（已按此执行）

- **只改 `unsuitable_for`**，追加 `"yin_deficiency"`，**保留原有值不动**。
  已核：这 10 味里 **9 味原有 `unsuitable_for` 非空**（多为 `damp_heat`，薏苡仁为
  `qi_deficiency, yang_deficiency`），**只有茯苓是空列表**。逐条 append，不整字段覆盖——
  覆盖会静默抹掉已有的湿热/气虚标注。
- **文本级精确替换**（按 id 定位块 + 定位 `"unsuitable_for"` 行，只重写该行），
  不用 `json.dumps` 整体回写——`herbs.json` 是**内联数组**风格，整体序列化会炸出
  上千行假 diff（Step 2 已踩过，见 `docs/herbs-9types-draft.md` 执行结果）。
  验收方式：`git diff --numstat` 恰为 **10 增 10 删**（数据行）＋ `_meta` 区块。
- **逐条复核落盘**：同一文件的多处编辑并行发出会出现「回执成功、内容未落盘」的静默丢失，
  本次改用单次脚本改写 + `git diff` 全量复核，避免踩坑。
- ⚠️ 本次踩到并已修正的一个坑：脚本回写时**在尾部多补了一个换行**（`split('\n')` 已保留
  末尾空元素，再补就多一行）。表现是 `git diff` 尾部凭空多一个空行，`numstat` 从 10/10
  变成 11/10。用 `rstrip('\n') + '\n'` 修正。
- `_meta.version` `0.2.0` → `0.3.0`；`_meta.constitution_extension.cautions_batch` 记录本批。
  另外一个编辑事故也被 `pytest` 前的 JSON 校验抓住：替换 `note` 行时把
  `constitution_extension` 的**闭合大括号**一起替掉了，导致 JSON 非法——
  **改 `_meta` 这类嵌套结构后必须立刻 parse 一次**。
- 未动 `review_*`、未改 `nature/flavors`、未碰 `food_properties.json`。
