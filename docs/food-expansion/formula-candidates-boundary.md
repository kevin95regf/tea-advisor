## 0. 一句话结论（先读这段）

**正常医生开的那种完整方剂，一般不应整方入库当自动推荐。**  
tea-advisor 的定位是「食物寒热查表 + 药食同源饮片/茶饮与家用汤建议」，不是开方系统；SPEC / Agent2 硬性边界写明：**不开方剂、不做君臣佐使、不出现方剂名、让模型结构上无方可开**（`SPEC.md` §1.3–1.4；`agent2_system.md` 硬性边界 2）。

能做的是三件事，且必须分清：

| 层 | 是什么 | 能否进自动推荐 |
|---|---|---|
| **A** | 药食同源范围内的**家用组合 / 食疗方名**（组成几乎都在 herbs/food 白名单） | **可以**做成独立的「命名汤模板 / 组合推荐」，但不是 CHM 处方剂量 |
| **B** | 经典方里拆出的**安全单味**补饮片库 | **可以**（只补单味，**不入库方名**）；与现有 P0 对齐 |
| **C** | 门诊常用完整方（六味、逍遥、补中益气、银翘、小柴胡等） | **不适合**自动推荐出汤药剂量；最多科普展示 / 外链 / 人工审核只读百科 |

## 1. 产品边界（诚实版）

### 1.1 现在系统实际在做什么

- 上半：食物寒热**查表**（确定性）。  
- 下半：在 **herbs 白名单**（当前 44 味，且合规核对要求贴近卫健委「食药物质目录」106 种）内，推荐 1–3 条冲泡/轻煮搭配；剂量有护栏。  
- 另有 `constitution_medication` **只读调理资料**，**不提供剂量、不进入茶饮推荐链路**（`SPEC.md`；`README.md`）。

### 1.2 为什么「医生开的那种方」不能整方进推荐

1. **辨证与剂量**：方剂剂量、加减、煎法依赖望闻问切与禁忌（十八反、十九畏、妊娠禁忌、毒性饮片、细料贵重药）。产品没有辨证闭环，自动吐「方名 + g 数」= 伪开方。  
2. **目录与合规**：推荐饮片应落在**药食同源 / 项目白名单**；门诊方大量君臣药（柴胡、黄芩、半夏、麻黄、白术、白芍、川芎、泽泻、牡丹皮、连翘…）**不在** `food_medicine_catalog.json` 的 106 种内。  
3. **工程已选的安全哲学**：「提示词里写十遍不要开方，不如让模型无方可开」——若入库整方并让 Agent 按方名出剂量，等于拆掉这道结构墙。  
4. **毒性 / 相反**：半夏、杏仁（苦杏仁口径）、白果、桃仁、麻黄等；以及十八反语境下的配伍——家用助手不应自动拼。

### 1.3 和「中药汤」用户诉求怎么对齐

用户想要「不局限于茶饮、也有中药汤」——合理路径是：

- **家用汤 / 药膳汤**（A 层命名模板 + B 层补单味），  
- 而不是把《方剂学》常用方（C 层）搬进自动推荐。

这与 `herb-expansion-soup-candidates.md` 的 P0（黄芪、党参、当归、砂仁、麦芽、木瓜、胖大海）同一方向。

## 2. 三层框架（A / B / C）

### A 层 — 食疗 / 家用组合（可做「配方模板」）

**准入条件（建议写成产品规则，入库前强制自检）：**

1. 方名在大众语境里首先是**食疗/家常汤**，或可改名为「××汤取向」以免处方感。  
2. 组成中**每一味**须属于：`herbs.json` 已有，或食物表已有，或已批准的 P0/P1 候选且属食药目录；**不允许**夹带目录外处方专药。  
3. **不写处方级汤药剂量**；若给用量，只用「食材级 / 家庭厨房约量」或「单味 catalog 已有 `max_daily_g` 封顶的泡煮量」，并带免责声明。  
4. 不进 Agent2 的「君臣佐使」叙述；模板由**人工策展**数据驱动，模型最多在白名单内解释，不能自由加减成方。  
5. 孕妇、哺乳、儿童、慢病、服药等仍走现有高风险闸门 → 空推荐 + 就医。

**已具备或接近具备的 A 层例子：** 四神汤、姜枣茶、清补凉取向、银耳莲子汤取向；当归生姜羊肉汤 / 芪枣鸡汤等在 P0 入库后可升格。

### B 层 — 只拆单味进饮片库（不入库方名）

从大众熟悉的经典方里，把**已在食药目录、适合煲汤/代茶**的味补进 herbs（与 P0/P1 表对齐），**产品文案禁止写「本方即逍遥散/补中益气汤」**。

| 来源方（仅作溯源，不入库） | 可考虑的单味 | 状态 |
|---|---|---|
| 补中益气汤 / 芪枣汤习惯 | 黄芪、当归 | P0 |
| 参类清补习惯（非四君子原方） | 党参（**不用人参**顶替出方） | P0；人参不在食药目录 |
| 消食类方习惯 | 麦芽、莱菔子 | P0 / P1 |
| 银翘类「凉性代茶」习惯 | 淡豆豉、桔梗、鲜芦根（目录名） | P1；**不**把连翘/荆芥/牛蒡子拉进来冒充银翘 |
| 六味「补肾」营销常见 | 山茱萸 | 最多 P2 + 特殊人群；**熟地/泽泻/丹皮不整方** |
| 肉汤化湿 | 砂仁 | P0 |

### C 层 — 门诊常用完整方（不自动推荐）

六味地黄丸、逍遥散、补中益气汤、银翘散、小柴胡汤、四君子汤、四物汤、二陈汤、桂枝汤、麻黄汤等：

- **组成含多味目录外药**或需辨证的毒性/峻药；  
- 即使用「党参代人参」等家用替换，**仍不是原方**，若以原方名自动推荐 = 误导；  
- 处置：**科普只读 / 外链药典或教材简介 / 人工审核百科**；剂量字段永久为空；**禁止**进入 `fallback_recommend` / Agent2 候选拼方。

现有 `GET /api/medication-reference` 模式（只读、无剂量、不进推荐）是 C 层唯一合理落点——且当前资料是体质干预指南摘要，**不是**方剂库；若要做方剂百科，应新开只读数据结构，与推荐链路硬隔离。

## 4. 产品建议：要「方剂感」，做 named soup templates，不做 CHM 处方库

### 4.1 推荐形态

```
SoupTemplate {
  id, display_name,          // 如「四神汤」「姜枣茶」；避免「××汤加减」
  kind: "food_therapy",      // 固定；不是 "chm_formula"
  components: [ {herb_id|food_id, role: "ingredient"} ],  // 全白名单
  kitchen_amount_hint?,      // 可选，家庭约量；禁止冒充处方剂量
  max_per_component_from_catalog,  // 沿用单味 max_daily_g
  cautions[], suitable_notes[],
  review_status: pending|approved
}
```

- **与 Agent2 隔离**：模板列表可由规则/UI 展示「家常汤参考」；Agent2 仍只输出白名单饮片搭配，**提示词继续禁止方剂名**，或仅允许引用已 `approved` 的 template id（白名单方名），禁止自由组方。  
- **不要**新建「方剂.json」把六味、逍遥的君臣佐使与 g 数写进去再让模型选用。

### 4.2 最适合先做的 3–5 个食疗模板名

| 优先级 | 模板名 | 前提 |
|---|---|---|
| 1 | **四神汤** | 无（四味已在库） |
| 2 | **姜枣茶** | 无 |
| 3 | **清补凉（白名单版）** | 固定玉竹/麦冬/百合/莲子/山药等已有味；拒绝外部包材未知味 |
| 4 | **银耳莲子汤** | 跨 food+herb；文案标明食疗 |
| 5 | **当归生姜羊肉汤取向** 或 **芪枣鸡汤取向** | 依赖 P0：**当归** 或 **黄芪（±党参）** 入库 + 羊肉/鸡肉食物 |

消食向「山楂麦芽饮」可作为第 6，卡在麦芽 P0 与哺乳 caution。

### 4.3 明确不建议自动推荐的方类

- 少阳和解、峻汗解表、攻下、含 **半夏/麻黄/柴胡/黄芩** 等非目录主药的汤方；  
- 以成药名（××丸、××散）直接映射出家庭煎服剂量；  
- 任何需要十八反检查才能安全共煎的组合；  
- 以「本方治疗××病」为卖点的条目（违反不诊断、不承诺疗效）。

### 4.4 和 P0 单味扩库的衔接

先落地 `herb-expansion-soup-candidates.md` 的 **Batch H1（P0×7）**，A 层模板 5、6、7 才有组成闭环；**不要**先做 C 层百科再倒逼开方。
