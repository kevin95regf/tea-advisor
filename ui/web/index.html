中医食性助手

这个程序的核心是：食物是寒是热，不靠模型猜，而是查表 + 纯规则判定， 并且每一档结论都能追溯来源。模型只负责把你打的字解析成食物、把结论写成人话。

建议按顺序试这 4 次

  1. 完成问卷后在「规则速览」输入饮食，再点「给我建议」——使用本机规则，不调用模型。切换到 API 对话后才会调用所选模型并产生费用。
  2. 把鼠标停在结果里任意一个食物标签上，会浮出它的判定来源与完整推导过程（如「查表 ｜ 置信度 90% ｜『麻辣烫』原形态下属性为热（查表直取）」）。这是本产品最重要的部分。
  3. 输入 我怀孕了，今天吃了火锅，能喝什么茶 —— 秒回，且不给推荐，只引导就医。这条不调用模型，免费。
  4. 输入一句表里没有的食物，如 晚上吃了佛跳墙 —— 看它会不会"装懂"（应当标记为模型推测或未判定，而不是给你一个确定结论）。

看到这些不是 bug

  • 满屏「待验证」：食性表中尚待专业人员审核的条目会保留标记，标记密度也是审核进度的可见反馈。
  • 属性显示成「未判定」：置信度低于 30% 时界面统一不显示寒热属性，这是安全设计，不是漏渲染。
  • 「麻辣烫」把「辣椒」也带出来了：关键词子串匹配的固有歧义（"麻辣烫"含"麻辣"），已在文档「已知局限」记录，需要别名库才能根治。
  • 复杂菜名无法按规则识别：表里没收录的整菜名可能无法由本机规则判定；API 对话中的模型推测会另行标注。

反馈时请带上

  • 你输入的原文、以及页面底部那行 request_id（便于我按请求定位日志）。
  • 你预期看到什么、实际看到什么。判断"属性对不对"请看标签悬停里的来源：查表与按烹饪方式推算是可以争论数据对不对的，模型推测本来就不保证准。
